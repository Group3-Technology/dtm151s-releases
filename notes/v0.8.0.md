## DTM 151 Teslameter Control 0.8.0

Desktop control and monitoring for the **Group3 DTM 151-S digital
teslameter** over a serial connection — live field and temperature readout,
real-time plotting, CSV logging, and a configurable derived measure.

This release adds support for connecting over a **fibre-optic (FTR) link**,
and for teslameters that have their echo switch turned on. If you connect
with a direct serial cable and have never changed DIP switch S2-4, nothing
about the application changes for you — upgrading is optional.

**New here?** Download the file for your platform below, then follow the
[install steps](https://github.com/Group3-Technology/dtm151s-releases#installing)
— there's a one-time approval on first launch, because the application isn't
code-signed. No installer and no admin rights are needed. The full **User
Guide** is included in the download, and `SHA256SUMS.txt` is attached if
you'd like to verify what you downloaded.

## What's new

### Fibre-optic links and echo-enabled teslameters

The application now works over a Group3 communication loop — the
arrangement a fibre-optic (FTR) link uses — and with teslameters whose echo
switch (DIP S2-4) is on.

On both of these, every command sent to the instrument comes back to the
application before the instrument's actual reply. Previously that returned
copy was mistaken for the reply, and connecting failed with an error about
an unexpected response from the device. The application now checks for this
when you connect and adapts to whatever it finds. Where the echo is coming
from the teslameter's own DIP switch, it also switches the echo off for the
session; on a fibre-optic loop the return is a property of the loop itself
and cannot be switched off, so the application simply accounts for it.

**Nothing is required from you** — no setting to change and no switch to
flip. The CONSOLE tab reports what it found each time you connect, so you
can confirm at a glance which kind of link you're on:

```
NOTE: [link: G3 loop returning commands (device echo turned off)]
```

## Changed

- **The CONSOLE tab notes your connection type on connect.** On a direct
  serial cable this reads `NOTE: [link: direct, commands not returned]`.
  It's informational — no action needed.

- **The included User Guide now covers macOS 15 (Sequoia) and later.**
  Apple removed the old right-click → **Open** route for approving
  unsigned applications. On macOS 15 or newer — including macOS 26 —
  double-click the app once, click **Done**, then go to **System Settings →
  Privacy & Security** and click **Open Anyway**. On macOS 14 and earlier,
  right-click → **Open** still works. The guide covers both, and there's a
  one-line Terminal alternative that works on every version.

## Upgrading from 0.7.3

Unzip and run as usual.

**Your saved settings, CSV log files and derived-measure presets are
unaffected.** Nothing has moved, no file format has changed, and no column
has been added or renamed.

Connecting to the instrument now begins with two short identification
queries before the first reading is taken. On a direct serial cable you
should notice no difference beyond the new CONSOLE line.

If the CONSOLE reports a link type that doesn't match how your instrument
is actually wired, or the application reports a link it cannot identify,
please get in touch and include what the CONSOLE tab shows.
