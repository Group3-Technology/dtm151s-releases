## DTM 151 Teslameter Control 0.10.0

Desktop control and monitoring for the **Group3 DTM 151-S digital
teslameter** over a serial connection — live field and temperature readout,
real-time plotting, CSV logging, and a configurable derived measure.

This release adds a download for **Intel Macs**, keeps Block captures on
an exact time grid, and makes CSV timestamps record when each reading was
taken. **Recommended for everyone**, and the only route for Intel Mac users.

**New here?** Download the file for your computer below, then follow the
[install steps](https://github.com/Group3-Technology/dtm151s-releases#installing)
— there's a one-time approval on first launch, because the application isn't
code-signed. No installer and no admin rights are needed. The full **User
Guide** is included in the download, and `SHA256SUMS.txt` is attached if
you'd like to verify what you downloaded.

## What's new

### A download for Intel Macs

The macOS download runs only on Apple Silicon Macs, so it would not open on
an Intel Mac. There is now a separate `G3_DTM151_Control-macos-intel.zip`
for those. Both macOS downloads need **macOS 15 (Sequoia) or newer** —
earlier releases said macOS 11, which was wrong.

---

## Fixed

- **Block captures drifted long.** A Block capture at a set rate took a
  few percent longer than it should, because one late reading pushed back
  every reading after it. Readings now land on a fixed 100 ms grid from
  the moment you connect, so a late one no longer delays the rest, and a
  Block capture takes the time you asked for.
- **`timestamp_iso` recorded when a row was written, not when the reading
  was taken.** It is now the PC's UTC time at the moment the reading was
  requested from the instrument — the same moment `t_seconds` is timed
  from. The status line's time matches it.
- **Once a second a reading could arrive late,** when the temperature and
  the range/filter checks fell on the same reading. They are now kept
  apart.
- **Pressing Connect during an automatic-reconnect countdown** could leave
  the countdown running, so it tried to reconnect again after you had
  already connected. Connecting yourself now cancels it.

---

## Changed

- **The Block rate in Hz is chosen from a list: 1, 2, 5 or 10 Hz.** These
  are the rates the 10 Hz reading divides into exactly. Other Hz values
  used to be rounded (3 Hz actually logged every 0.3 s). A rate in seconds
  can still be any whole number.
- **A missed reading leaves a gap in a Block log** instead of shifting the
  rows after it. You'll see it as a longer step in `t_seconds`, and the
  capture ends one period later for each missed row.
- **Use `t_seconds` for elapsed time.** `timestamp_iso` follows the PC
  clock, so if the clock is corrected during a long capture (internet time
  sync, sleep), differences between `timestamp_iso` values can differ
  slightly from the `t_seconds` differences.

## Upgrading from 0.9.0

Unzip and run as usual. On an Intel Mac, take the new `-macos-intel` zip.

**Your saved settings, CSV log files and derived-measure presets are kept.**
Nothing has moved, and no CSV column has been added or renamed. One thing
to know:

- If your saved Block rate is a Hz value that is no longer offered, it is
  set to the nearest one in the list the first time the application starts
  (3 Hz becomes 2 Hz, 4 Hz becomes 5 Hz), and that is saved. Check the
  rate before your next Block capture if you used one of those.
